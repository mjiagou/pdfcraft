## 一、 主流邮箱与政企系统附件大小限制标准对比

在压缩之前，明确目标体积是避免“重复返工”的关键。根据 **RFC 2046** 与 **RFC 5322** 规范，邮件系统在传输二进制附件时需进行 Base64 编码，这会导致附件原始体积在传输时膨胀约 **33%~37%**。因此，服务商标称的限制往往比实际允许的本地文件大小更苛刻：

| 平台 / 服务商 | 官方标称上限 | 建议本地预留安全体积 | 常见拒收提示 / 限制机制 |
| :--- | :--- | :--- | :--- |
| **Gmail** | 25 MB | ≤ 18 MB | 自动强制转为 Google Drive 链接（外部访客常无权限） |
| **Outlook / Office 365** | 20 MB ~ 25 MB | ≤ 15 MB | 报错 `552 5.3.4 Message size exceeds fixed limit` |
| **腾讯企业邮 / QQ 邮箱** | 50 MB（普通附件） | ≤ 35 MB | 超大附件依赖中转站（30天过期失效） |
| **网易企业邮 / 163 邮箱** | 20 MB ~ 50 MB | ≤ 15 MB | 超限直接中断发送 |
| **国家公考 / 事业单位招录** | 1 MB ~ 2 MB | ≤ 1.8 MB | 前端直接拒绝上传校验 |
| **高校推免 / 考研报名系统** | 2 MB ~ 5 MB | ≤ 2 MB | 提示文件解析超时或格式异常 |

> 💡 **专家建议**：为了确保接收方在各类移动终端与桌面客户端均能顺利即时下载，商务往来 PDF 文档建议控制在 **5MB 以内**；政务申报类建议严格控制在 **2MB 以内**。

## 二、 深度解构：为什么你的 PDF 会动辄数十兆？

根据 **ISO 32000-1 (PDF 1.7)** 与 **ISO 32000-2 (PDF 2.0)** 国际规范，PDF 本质上是一个包含多种复杂流对象（Stream Objects）的复合容器。导致其体积膨胀的核心原因通常有三项：

```
[ PDF 复合容器结构 ]
├── 1. 结构与元数据 (XRef Table, Trailers, History) -> 冗余增量流
├── 2. 文本与矢量轮廓 (Glyphs, Fonts)             -> 未子集化的大字库 (15MB+)
└── 3. 光栅位图图像流 (Raster Bitmaps)             -> 300~600 DPI 未压缩原始图 (占体积 80%+)
```

1. **未压缩的高 DPI 光栅扫描图（主要元凶）**  
   办公室大型扫描仪或手机全能扫描王拍摄的照片，默认采用 300 至 600 DPI 的原始彩色点阵（Bitmap）存储。单页 A4 高清扫描图如果不经过有损/无损量化，体积往往高达 **5MB~12MB**。10 页合同即可轻松突破 60MB。
2. **未进行子集化的完整字体嵌入（Font Embedding）**  
   部分设计软件在导出 PDF 时，会将整套中文字体库（如思源黑体、方正兰亭，单套体积可达 15MB~30MB）完整打包注入文档中，哪怕整篇文档仅使用了其中的几十个汉字。
3. **多次增量保存带来的历史版本与无效垃圾流（Dead Streams）**  
   PDF 规范支持增量更新（Incremental Update）。在 Adobe Acrobat 或 Photoshop 中反复编辑保存后，旧版本的历史图层、编辑痕迹与已被删除页面的游离流并未真正抹除，依然潜藏在交叉引用表（XRef）之后。

真正的专业级压缩引擎，核心逻辑在于**重构对象树、精确降采样位图、剥离无用对象，同时百分之百保留文字字形（Glyphs）的数学矢量轮廓**。

1. 使用浏览器打开 [PDF 在线压缩工具](/zh/tools/compress-pdf)。
2. 将需要缩小的 PDF 拖入界面正中的虚线放置区，或点击“选择文件”。支持多文件批量排队处理。

### 第二步：根据使用场景选择智能预设

* **轻度压缩（高保真印刷级）**：仅重构交叉引用表与剔除废弃元数据，适合对艺术品摄影集、彩色宣传册进行微调。
* **推荐平衡（商务首选，强烈推荐）**：将扫描位图自适应重采样至 150 DPI（满足视网膜屏与常规彩色激光打印机精度），同时完整保留矢量字形。体积缩减 60%~85%，适用于绝大多数工作邮件、合同归档与即时通讯传输。

## 六、 资深专家答疑（FAQ）与常见误区避坑

### Q1：为什么有些 PDF 压缩后体积几乎没有任何变化？
**答**：这通常由两种情况导致：
1. **纯文字排版文档**：文档本身全部由 TrueType 字符与矢量线条构成，没有位图。这种文档本身仅有几百 KB，已经处于极小体积状态。
2. **已经经过深度压缩的二次文件**：文件内的图片已经采用了高度压缩的 JBIG2 或 WebP 格式，信息熵极高，二次压缩不会再有缩减空间。

### Q2：压缩会破坏 PDF 中的可复制文字或可检索性吗？
**答**：**绝对不会。** TPSH PDF 的底层处理管线严格隔离了 Content Stream 中的文本绘制算子（如 `Tj`, `TJ`）与字体子集对象。压缩仅针对 XObject 图像对象进行量化优化，文档原本的文字选择、划线批注、复制粘贴与全文搜索能力 100% 完整保留。

### Q3：断网状态真的可以使用吗？如何验证是否有数据被偷偷上传？
**答**：完全可以。你可以按键盘上的 `F12` 打开浏览器“开发者工具”，切换至 **Network（网络）** 标签页，勾选“Offline（离线）”或直接拔掉网线，然后进行压缩。你会发现处理依然正常飞速完成，网络面板中没有任何向服务器发送的文件 Payload，真正做到 100% 本地隐私安全。
